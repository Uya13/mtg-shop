# Подготовка к защите

## Что делает приложение

Сервис хранит готовые колоды MTG как товары магазина. Названия карт — описание
состава товара. У каждой колоды есть артикул, цена и остаток. Поступление
увеличивает остаток, продажа уменьшает. Каждая операция сохраняется в журнале.

## Что нужно понимать в коде

1. `models.py` описывает таблицы. `decks` связан с несколькими строками
   `deck_cards` и несколькими операциями `movements` через `deck_id`.
2. `schemas.py` проверяет JSON: отрицательная цена, пустое название и нулевое
   количество отклоняются с HTTP 422 до выполнения бизнес-логики.
3. `get_session` выдаёт отдельную сессию БД запросу и закрывает её после ответа.
4. `add_movement` блокирует строку колоды в PostgreSQL, проверяет остаток,
   меняет его и добавляет операцию. `commit` сохраняет оба изменения вместе.
5. `Decimal` и `Numeric(10, 2)` используются для денег. Сумма выручки берётся
   из сохранённых цен операций, а не из текущей цены колоды.
6. `docker-compose.yml` задаёт сеть, сервисы, тома, переменные и проверки здоровья.
   `depends_on: service_healthy` позволяет дождаться готовности базы.
7. `/health` делает `SELECT 1`: он проверяет и API, и доступность базы.
8. Prometheus опрашивает `/metrics`, Grafana строит графики по этим данным.
9. Jenkins исполняет `Jenkinsfile`: проверки, сборка, доставка образа
   на вторую машину. Ошибка тестов останавливает следующие стадии.

## Сценарий показа на 7–10 минут

1. Объяснить задачу и показать схему компонентов из файла «05 Запуск проекта и схема компонентов» в папке разборов.
2. Показать `docker compose ps`: четыре здоровых контейнера.
3. Через Swagger создать товар, принять 5 колод, продать 2.
4. Попытаться продать 4: получить 409, убедиться, что остаток 3.
5. Показать журнал и сводку, затем графики запросов в Grafana.
6. Показать GitHub и две разные машины.
7. Изменить сообщение `/health`, сделать commit/push, показать пайплайн и обновление.

Запуск пайплайна занимает дополнительное время; заранее выяснить его длительность.

## Ответы на типичные вопросы

**Зачем журнал?** Чтобы знать, почему изменился остаток, и хранить цены прошлых продаж.

**Почему нельзя удалить товар с операциями?** Иначе потеряется связь с историей учёта.

**Что будет при двух одновременных продажах?** PostgreSQL последовательно выдаст
блокировку строки. Вторая транзакция увидит уже изменившийся остаток. Это проверяется тестом.

**Что хранится в томе?** Данные PostgreSQL, история метрик Prometheus и настройки Grafana.
Удаление контейнера само по себе не удаляет именованный том.

**Где секреты?** Локально в игнорируемом `.env`, в CI — в Jenkins Credentials.
В Git хранится только пример без настоящих секретов.

**Почему нет интерфейса сайта?** Он необязателен по заданию; API демонстрируется через Swagger.

**Ограничения?** Нет проверки карт и правил MTG, возвратов, ролей пользователей,
миграций схемы и доступа из интернета. Это небольшой внутренний учебный сервис.
